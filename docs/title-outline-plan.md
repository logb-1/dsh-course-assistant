# 标题与目录：诊断报告与修改方案（2026-10-31）

> **状态：P0 / P1 / P3 + P2a 已在 1.15.0 实现**（`core/titles.js`、`core/outline.js`、`core/report.js`、
> 摘要提示词 v6、`chapterTitles` 配置）。P4（表格/目录页识别）只做了「PDF 表格行不当章节」这一条。
> 下面是当时的诊断与方案原文，保留作为决策记录。
>
> 结论先说：**目录偏差不是"模型总结得不好"，而是分章前的本地结构识别有缺陷**。
> 六个真实课件里有五个能稳定复现：章名是页首行碎片、面包屑或代码行，课程名是"幻灯片 1"。
> 下面给出证据、根因分层，以及一套**不额外调用模型**（可选再加一次）的修改方案。

---

## 一、用户可见的症状

1. 章节目录里出现 `异常`、`cat`、`class`、`A safe vari`、`：\" << username <<` 这种碎片。
2. 同一章名重复：`课程导读（p16–20）`、`课程导读（p21–25）`。
3. 课程名变成 `幻灯片 1` / `幻灯片 1: 第10章 异常与断言`，报告标题与导出文件名跟着错。
4. 边界随意：67 页的 PPT 被切成 13 个"5 页一章"，与自己课件的结构无关。
5. 表格/星标行被当成章节，目录顺序错乱、同名章节出现两次。
6. 课程名取成文档第一个标题（`前言与使用说明`）。

- `实验1` 的页标题 `课程导读` 出现 8 次（面包屑占位符），导致按"首行"命名时反复撞名；

## 三、根因分层（都指向分章之前）

### L1 页标题抽取太粗

- `core/pdf.js:1105 pickTitle()`：取正文前 5 行中长度 2–60 的第一个非页码行。
  → 于是 `8.0`、`cat`、`#includ fstrea`、`：\" << username <<` 都成了"标题"。
- `core/ooxml.js:82 extractSlide()`：只认 `title` / `ctrTitle` 占位符，没有"这个占位符是不是面包屑"的判断。
- `core/ocr-triage.js:124`：OCR 换掉页面正文后，标题只在**原来为空**时才重算
  （`title: page.title || firstLine(...)`），所以 OCR 读出的好标题进不了目录。

### L2 分章信号不足时退回定长切块

- `core/outline.js:194 chaptersByChars()`：按 ~700 字累积，等价于"5 页一章"，章节名取第一页的标题。
  → `实验1` 的 13 章就是这么来的，边界与课件结构无关。
- `core/outline.js:332 headingLevelOf()`：`一、`、`第N章`、`x.y` 都被当成同级 level 1。
  → 混合体例的文档（`一、考情分析` 与 `第 2 章 …` 并存）会把表格里的 `第 2 章` 也当章节。
- 表格区域没有识别：`计算机系统基础 复习&自学大纲.pdf` 第 1 页的"文件名 ↔ 实际内容对照表"被当成章节开头。

### L3 命名只看"是不是通用词"

- `core/outline.js:524 informativeTitle()`：只有 `isGeneric()`（`主要内容`/`小结`…）才触发替换；
  `cat`、`class`、`第 1 部分`、`、有虚函数时…` 都不在通用词表里 → 原样保留。
- `core/outline.js:288 chapterTitleFor()`：兜底 `第 N 部分`，直接出现在成品报告里。
- `core/outline.js:457 mergeSameTitle()`：同名章加 `（p16–20）` 后缀——能区分，但读者看到的是页码而不是内容。

### L4 课程名没有选择逻辑

- `core/pipeline.js:238` 只处理"整个标题恰好是 `幻灯片 12`"的情况，`幻灯片 1: 第10章 …` 这种带后缀的漏网。
- `core/ooxml.js:241 guessDeckTitle()` / `parseMarkdown`：课程名 = 第一个标题，遇到"前言与使用说明"就错。
- `core/pdf.js`：`outline[0]?.title || pickTitle(第一页)`，没有质量判断。

### L5 没有自检，也没有呈现层的兜底

- `core/report.js:29 toc()`：`subs` 原样输出（最多 6 条），碎片会直接进目录。
- 全流程没有任何"标题质量"警告；坏标题会一路进报告、B 站查询、文件名。

## 四、修改方案

分四块，**P0/P1/P3 零模型调用、纯本地**，P2 可选。

### P0 标题卫生（新增 `core/titles.js`，约 180 行）

```js
cleanTitle(text)      // 去「幻灯片 N:」「Slide N:」「第 N 页」前缀、首尾符号、截断尾标点、压缩空白
titleScore(text, ctx) // 0–1 分 + 否决规则
pageTitles(doc)       // 逐页重新选标题：占位符/最大字号行 → 正文前 8 行，取最高分
dropFurniture(pages)  // 在 ≥40% 页面重复（且 ≥3 次）的标题记为"家具"，不参与命名
```

否决规则（每条都对应上表的一个坏样本）：

| 规则 | 命中的坏标题 |
|---|---|
| 纯数字/编号（`^\d+(\.\d+)?$`） | `8.0` |
| 像代码（`{ } ; = < > #`、`#include`、`printf`、`std::`） | `#includ fstrea`、`class B : public A` |
| 中文 < 3 字且不含字母数字词 | `cat`、`class`、`异常` |
| 以 `，、）】」"` 开头或以 `，、：` 结尾（被截断） | `作为一个`、`、有虚函数时…` |
| 长度 > 40 或 < 4 | — |
| 本页"家具"（重复页眉） | `课程导读`、`8.0` |

接入点：

1. `core/text.js#cleanDoc`：解析后统一跑一遍 `pageTitles(doc)`（所有格式共用，避免每个 parser 各写一套）。
2. `core/ocr-triage.js#applyOcrPages`：OCR 换过正文的页面**重算标题**（不再"只有空标题才补"）。
3. `core/outline.js#chapterTitleFor` / `chaptersFromSectionNumbers` / `chaptersByChars`：一律用清洗后的标题。
4. `core/pipeline.js`：课程名走新的 `pickCourseTitle()`（见 P3）。

**预期**：L10/L12 不再出现 `8.0`/`cat`/代码行章名（改为关键词兜底，如 `第 3 章 异常处理`）；
`实验1` 的 `课程导读` 撞名消失。

### P1 分章边界（改 `core/outline.js`，约 150 行）

1. **标题变化分组**（替代 `chaptersByChars` 的固定 700 字）：
   - 逐页取"有效标题"（P0 之后，家具已剔除）；
   - 标题变化且当前章 ≥ 1200 字时开新章；不足 500 字的章并入前一章；
   - 章数越界（>22 或 <2）时退回原定长切块；
   - **覆盖率闸门**：有效标题占比 < 30%（L10/L12 这种文字层碎掉的导出件）说明标题信号不可用，
     直接走定长切块 + 关键词命名，避免 1–2 个碎片标题把整份课件切成一大章。
   - 原型实测（`实验1`）：**13 章（3 个"课程导读"）→ 14 章**，标题变成 `课程实训案例引导`、`接口设计`、
     `为什么做开发者测试？`、`测试防护网：正交分解法`、`代码管理`……
2. **主导标题层级**：统计 `一、` 与 `第N章` 两种体例的行数，多者定为主层，另一层降为 subs。
   - 原型实测（`复习大纲.pdf`）：**11 章（乱序+重复）→ 4 章**（`一、考情分析`／`二、分章复习大纲`／`三、B 站…`／`四、三轮…`）。
3. **同名章去重**：`mergeSameTitle` 之后，若同名章的页范围紧邻（间隔 ≤1 章）直接合并；
   否则后缀改成 `（续）` 或 `（p16–20）` 仅在页范围确实不连续时保留。

### P2 命名增强（可选，两档）

- **P2a（推荐，零额外调用）**：章节摘要提示词（v6）加一个 `title` 字段，模型读完本章顺手给标题；
  本地校验（4–24 字、不含编号/页码/代码、与本章关键词或正文有交集），只有比现标题分高才采用；
  全部章节结束后做一次去重（重复的追加区分词）。
- **P2b（可选，+1 次调用）**：`chapterTitles: 'auto' | 'rules' | 'llm'`。`auto` = 仅当有低分/重复标题时，
  发一次全课程命名调用（每章：现标题 + TF-IDF 词 + 首 160 字），输出 8–22 个短标题，
  校验同上；缓存 30 天。MAX 模式默认 `auto`。

**注意**：P2a 会改摘要缓存键（prompt v5→v6），已缓存章节需重算一次。

### P3 课程名 + 目录自检 + 呈现（改 `core/outline.js`、`core/report.js`、`core/pipeline.js`，约 120 行）

1. `pickCourseTitle(docs)` 候选顺序：
   文件名（去扩展名）→ PDF 书签首条 → 第一个通过质量分的页标题 → 首个章节标题；
   拒绝 `幻灯片 N`、`前言`、`使用说明`、`目录`、纯编号，以及"看起来就是章节级"的标题（`第 N 章 …` 且 ≥3 章）。
   → `L10` 得到 `L10_C08_多态与虚函数`（或首个好页标题），不再是 `幻灯片 1`。
2. `job.outline.diagnostics = { badTitles: [...], duplicates: [...], fallbackTitles: n, courseTitleSource }`；
   报告头部加一行「目录自检：12 章中 2 章标题由关键词兜底」；`badTitles > 0` 时进 warnings。
3. `toc()`：子标题过一遍标题质量分（丢弃碎片）、去重、最多 4 条；为空时用该章 `keywords` 兜底。
   → `实验1` 目录里不会再出现 `10.1×`、`pu`、`vitru` 这类条目。

### P4 表格/目录页识别（可选，放在最后）

- 规则：连续 ≥5 行短行（≤30 字）且 ≥30% 含 `|`/`→`/`.pptx` 等表格特征 → 该区域内的"标题行"不作章节。
- 只影响 `复习大纲.pdf` 这类"把讲义做成报表"的导出件；风险低，但收益也低，建议 P0–P3 落地后再看。

## 六、测试与验收

**单测（合成夹具，`--unit`）**

1. 标题否决：`8.0`、`#include <iostream>`、`cat`、`、有虚函数时…` 全部被拒；`第 3 章 异常处理`、`测试防护网：FIRST原则` 通过。
2. 家具：10 页里 5 页相同标题 → 判定为家具，改用次优行。
3. `cleanTitle`：`幻灯片 1: 第10章 异常与断言` → `第10章 异常与断言`；`★★★★ 第 8 章 异常和中断（投入 12% 时间）` → `第 8 章 异常和中断`。
4. 主导层级：混排 `一、`+`第N章` 的文本只切 4 章且 `第N章` 进 subs。
5. 标题变化分组：3 页一组的合成课件切出预期章数与标题；过碎时自动合并。
6. `toc()` 过滤：含 `pu`、`10.1×` 的 subs 不出现在目录里。

**真实课件（`--real`，本机有文件时）**

1. `L10`/`L12`：课程名不含「幻灯片」；章名不含代码字符、纯数字、`第 N 部分`；≥70% 章名 ≥4 个汉字。
2. `实验1`：不再有重复章名；章数 8–18；`课程导读` 不作为章名。
3. `deck`（`关上800美元`）：`§ 01 制度背景` 等 10 个章名**逐字不变**（防止清洗过度）。
4. 现有 gold（`deck-800`）边界指标不退化：windowdiff ≤0.25、F1 ≥0.85。

## 七、风险与回滚

| 风险 | 控制 |
|---|---|
| 清洗过度，把合法标题删掉 | 否决规则只针对明确坏形态；`deck` 的 § 章名作为回归守门 |
| 标题变化分组切得太碎 | 最小章长 1200 字 + 上限 22 章 + 越界退回定长切块 |
| 家具阈值误判（有些课件确实每页重复节名） | 只在**命名**时剔除，正文不动；阈值 40% 且出现 ≥3 次 |
| P2b 增加调用/延迟 | 默认 `auto`（仅低分时触发），可 `rules` 关掉；缓存 30 天 |
| 缓存失效（prompt v6） | 只影响章节摘要缓存，本地兜底仍可用 |

## 八、建议实施顺序

1. **1.15.0**：P0 + P1 + P3（纯本地，零新增调用）→ 预期解决 80% 的目录问题。
2. **1.16.0**：P2a（摘要顺带命名，零额外调用）；实测不足再开 P2b（单次命名调用）。
3. **1.17.0**：P4（表格/目录页识别）——按需。

**决策点**：是否接受 P1 改变现有章数（如 `实验1` 13→14 章、`复习大纲.pdf` 11→4 章）？这会让旧报告的分章与新的不一致，
但旧任务有 `outline.boundaries` 锁定、重跑沿用旧边界，不会串号。
